# Unarmed-defect routing — parking a finding instead of fixing it inline

Migrated detail for `orchestrating-delivery` Phase 2 — it runs **inside step 5, before any issue is
mapped to the sniper**. The law is `rules/unarmed-defects.md`; this file is the orchestrator's
procedure for applying it.

**Arming triage — an UNARMED finding never becomes an inline fix.** Before mapping issues to the sniper, split the collected verdicts (compliance + adversary + security + gates) on the arming axis each finding declares at the head of its `description` (`ARMED|UNARMED · REPRO: …`). A head reading `ARMED (contested: …)` is the cross-family merge reporting that the two families DISAGREED and that it resolved conservatively — treat it as armed, and never re-park it on the strength of the losing family's text.

- **ARMED → the normal flow below.** So does a finding with **no** arming declaration, a malformed one, or any case you are unsure about — the absence of a classification is not a classification, and "in doubt → ARMED" is the standing default.
- **UNARMED → excluded from the applied set**, and only when the park is COMPLETE: the coincidence the trigger needs, the cited reason intended-scale operation does not produce it, the **quoted source** of that intended scale (spec/PRD/locked decision — never inferred from seeds or fixtures), and a rearm observable **you verified false today**. You have a shell and the eyes largely do not — run that check yourself. Any part missing → treat it as ARMED and fix it. `REPRO: not-attempted` is never parkable.
- **Out of reach of this axis entirely:** a gate failure, a compliance `fail` / VIOLATED-locked-decision, a security finding whose trigger is deterministic, and anything wrong 100% of the times its path executes. Those are scope, not rarity.
- **Parking is the orchestrator's call, on the record — never a hand's and never an eye's.** The eyes propose; the `sniper` never reclassifies (it fixes or it escalates). Never park because the fix is expensive, out of `scope_paths`, or out of budget — arming is a property of the trigger, never of the diff. That case is an escalation.

Every parked finding produces BOTH, **in every mode** — FULL per-task, LIGHT's single upfront pass, the Phase 0 upfront spec-adversary (where no PR exists yet, so the issue is the only possible record), fix mode, and Phase 3:

1. **An operator warning in pt-br, product-language** — "hoje não existe um segundo usuário no mesmo grupo; quando existir, a mensagem dele some" — INTERACTIVE at the next checkpoint, HEADLESS as a line in the draft PR body.
2. **A tracked issue** via `creating-issues`, carrying the trigger precondition and the rearm observable in the body. **The issue is the only terminal of a park.** `findings.md` and `shared_context.md` are run buffers the harvester deletes at the end — a park recorded only there is a deleted finding with extra steps. Before filing, search open issues by the full `(scope, category, evidence)` triple — the same key the cross-family dedup uses, never `scope + category` alone, which collapses two genuinely different defects in one file and one failure class onto a single park — and update that issue instead of opening a duplicate each round. A near-match differing on `evidence` is a NEW finding.

**A parked finding does NOT block delivery, and does NOT lower a severity.** It sets neither `openRisk` nor `unresolvedBlockingAdversaryFinding` in the Phase 3 verdict, and the shipper's delivery-time open-risk check does not fire on it — its record is the tracked issue, not the PR risk state. Without this, "don't fix now" would silently mean "never merge". Symmetrically, the honest severity written by the eye stands: a parked `high` is still counted and reported as a `high`, and the security eye's `UNSAFE` verdict counts **ARMED** findings only (an unarmed `medium` that kept the verdict UNSAFE would deadlock the run — routed away from the sniper, nothing changes, next audit returns UNSAFE again, forever).

**Effect on the sniper dispatch:** the batch still resolves over the APPLIED set. If the only fail-class finding was parked, the remaining batch legitimately dispatches below `hand_tiers.medium` — that is the floor working on the real applied set, not a floor violation. And `regate-pending` is stamped only for a HIGH that actually reaches the sniper, so a parked HIGH never opens a rail nothing can close.

**Virgin re-entry — a park is not self-idempotent.** The adversary re-enters fresh-virgin on every re-dispatch and WILL re-find the parked defect; its own "in doubt → ARMED" default would then dispatch a sniper on what you just parked, or file the same issue again. Carry the park forward through the channel that already exists for exactly this: write it as a `### DEFERRED-RISK: <task-id>` block whose `falsify` line carries the **park's premise — the NEGATION of the rearm observable** (`no shard hosts more than one tenant`), never the observable itself, and whose `guards` names the state entity. Backwards, it asks the re-dispatched adversary to disprove that the defect fires — i.e. to CONFIRM the park, the opposite of a re-attack. **Exit clause:** a park-sourced note resolves when its rearm observable becomes true or the defect is fixed, not under the channel's ordinary diff-plus-frozen-test retention rule, which a runtime threshold can never satisfy. The deterministic pre-dispatch grep folds it into the adversary's L2 contract as a "falsify these premises" directive **without leaking any prior verdict**, so the virgin contract holds intact.
