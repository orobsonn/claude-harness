# Baseline de testes — reconstrução do plugin da lane OpenCode

**Data da medição:** 2026-07-30
**Escopo:** PRs 1–6 de `docs/prd/oc-plugin-rebuild.md` (Caminho A, cirúrgico)
**Registrada por:** PR 1 (rede de segurança), conforme §5 P5 do PRD.

## Regra

**Nenhum PR do plano mergeia acima destas baselines.** Um PR pode reduzir o número de testes
(a poda apaga módulos e seus testes junto), mas **não pode aumentar o número de falhas** nem
introduzir falha nova nos escopos abaixo.

Há duas baselines de escopo do CI porque **as duas plataformas não medem a mesma coisa**. A que
decide merge é a do CI. A local existe só para o operador saber o que ignorar na própria máquina.

## Baseline 1 — lane OpenCode

```
node --test "core/opencode/**/*.test.mjs"
```

| Métrica | Valor |
|---|---|
| tests | 742 |
| pass | 742 |
| fail | 0 |

Esta é a baseline **de trabalho** do plano: verde absoluto, sem falha tolerada. Qualquer
falha aqui, em qualquer PR, é regressão introduzida pelo PR. Vale igual no CI e em macOS.

## Baseline 2 (autoritativa) — escopo do CI, no CI

```
node --test "core/**/*.test.mjs" "modules/**/*.test.mjs" "scripts/**/*.test.mjs"
```

(`.github/workflows/ci.yml:29`, runner `ubuntu-latest`, Node 22)

| Métrica | Valor |
|---|---|
| tests | 2997 |
| pass | 2996 |
| fail | **0** |
| skipped | 1 |

Medido no run **30558600276** do workflow CI do **PR #606** (`conclusion: success`, sha
`33d64a6`; árvore bit-idêntica à `main`).

**É esta a baseline de merge.** No CI, **qualquer falha é regressão** — não existe falha
tolerada, não existe conjunto conhecido a descontar. O número de testes cresce ou diminui
conforme o PR; o número de falhas é zero, sempre.

## Baseline 3 (informativa) — o mesmo comando em macOS

Na máquina local (darwin 25.5.0, Node v22.22.2) o mesmo comando dá **28 falhas**. Elas são
artefato do ambiente local, **não propriedade do repo**: não existem no CI.

Atribuição real, medida arquivo a arquivo, cada um **isolado**:

| Arquivo | fail (isolado) |
|---|---|
| `core/vps/cron-a-dispatch-obs.test.mjs` | 11 |
| `core/vps/cron-a-dispatch-capture.test.mjs` | 10 |
| `core/vps/cron-a-dispatch-fixmode.test.mjs` | 4 |
| `core/vps/notify-wiring.test.mjs` | 2 |
| `core/claude-code/skills/initializing-projects/references/vendor-core.test.mjs` | 1 |
| **total** | **28** |

Arquivos verificados que **não** contribuem nenhuma falha: `scripts/cutover-preflight.test.mjs`
(6/6 pass), `core/vps/cron-a-dispatch-seed.test.mjs` (54/54), `core/vps/cron-a-dispatch.test.mjs`
(39/39).

São **duas causas distintas**, não uma:

1. **`core/vps/*` (27 falhas)** — precondição de ambiente: o dispatch não consegue abrir a sessão
   `tmux` nesta máquina. A asserção que quebra é literalmente
   `dispatch must spawn the tmux session` (`core/vps/cron-a-dispatch-capture.test.mjs:217`); as
   demais caem em cascata (`Cannot read properties of undefined (reading 'args')`), lendo o
   resultado do spawn que nunca aconteceu.
2. **`vendor-core.test.mjs:1037` (1 falha)** — `/var` vs `/private/var`: o `tmpdir()` do macOS é um
   symlink e o teste compara o path literal contra o realpath.
   ```
   + actual:   '/private/var/folders/05/.../vc-target-rHCbd4'
   - expected: '/var/folders/05/.../vc-target-rHCbd4'
   ```
   O `tmpdir()` do ubuntu é `/tmp`, sem symlink — por isso esta falha **não existe no CI**.

**Elas reproduzem isoladas.** A tabela acima é inteira de runs de arquivo único. Não é
interferência de run paralelo: o run completo em macOS produz **o mesmo conjunto de 28**, com a
mesma distribuição por arquivo (medido com o PR 1 aplicado: 3011 tests / 2982 pass / 28 fail /
1 skipped).

## Critério de aceite dos PRs 2–6

- **No CI (o que decide o merge):** `fail` deve ser **0**. Qualquer falha, em qualquer arquivo,
  é regressão do PR. Baseline 1 (`core/opencode`) igualmente em 0.
- **Localmente em macOS:** o critério não é um número solto — é o **conjunto nomeado** na
  Baseline 3 (os 4 arquivos de `core/vps` + `vendor-core.test.mjs:1037`). Falha em qualquer
  arquivo fora desse conjunto é regressão, mesmo que o total continue 28.

Atenção para os PRs 2 e 3: `vendor-core.test.mjs` é **exatamente** um dos arquivos que eles
editam. A falha conhecida ali é a linha 1037 e só ela — qualquer outra falha nesse arquivo é do
PR, não do macOS.

## Correção ao PRD

O PRD (`docs/prd/oc-plugin-rebuild.md` §5 P5) afirma **"2997 testes com 28 já falhando"**.
**Isso está errado.** As 28 são locais de macOS; o CI roda os mesmos 2997 testes com **0
falhas** (run 30558600276). Este documento é a correção — e o PRD deve ser lido com ela.

O erro não era cosmético: tratado como propriedade do repo, "28 falhas toleradas" licencia até
28 regressões reais passarem como "bate com a baseline" no lugar onde os PRs de fato mergeiam.

## Por que registrar isto no primeiro PR

O modo de falha que governa o plano (§5 P0) é que **plugin quebrado é pulado pelo OpenCode em
silêncio**: `EXIT=0`, zero log, os outros plugins carregam normalmente. Um número de testes
"verde" sem baseline registrada não distingue "o gate passou" de "o gate não existe mais".
Estas baselines são o denominador contra o qual os PRs 2–6 são medidos — e um denominador com
atribuição errada é a mesma rede de papel que o §5 P6 denuncia, um nível acima.
